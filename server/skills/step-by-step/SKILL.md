# 按顺序解决问题

用标签表示进度：`todo`（待办）、`doing`（进行中）、`done`（完成）、`skipped`（跳过）。同一时刻只有一个节点是 `doing`。

## 流程

1. **理解问题**：需求有歧义时用 ask_user 问清楚；能合理假设的就直接假设。
2. **建立清单**：新建一个主题节点作为清单，标题写「待办：<问题>」，摘要说明整体目标。
   每个步骤建成它的子节点，标签 `todo`：标题是步骤名，摘要写这一步要产出什么。
   步骤要具体、可独立完成、按执行顺序创建，一般 3~8 项。
3. **向用户确认清单**：清单建好后停下来，用一两句话请用户确认或调整，等用户回复后再开始。
4. **逐项解决**：每次先用 `canvas_list` 传 `tag=todo` 找到最前面的待办，严格按顺序做，一次一项。
   - 开始前把它的标签 `todo` 换成 `doing`（用 addTags / removeTags）。
   - 完成后把结论写进该节点的正文，摘要改为一句话结论，标签换成 `done`。
   - 做不下去或不需要了，换成 `skipped`，并在正文里写明原因。
5. **推进**：每完成一项，用一句话汇报，然后直接做下一项，不必每步都等用户。遇到必须由用户决定的事再用 ask_user。
6. **收尾**：`todo` 和 `doing` 都没有了，就在清单节点下新建「结论」子节点，汇总各步结论与整体答案。

## 注意

- 用户可能手动改了标签或节点：以白板上现在的标签为准，不要凭记忆。
- 用户中途插话或改需求时，先更新清单（增删改步骤），再继续。
- 不要提前做后面的步骤，也不要把多项合并成一次完成。
