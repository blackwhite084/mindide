# 按顺序解决问题

## 流程

1. **理解问题**：需求有歧义时用 ask_user 问清楚；能合理假设的就直接假设。
2. **建立清单**：新建一个主题节点作为清单，标题写「待办：<问题>」，正文用 markdown 复选框列出所有步骤：
   `- [ ] 步骤`。步骤要具体、可独立完成、按执行顺序排列，一般 3~8 项。
   每个步骤再建一个子节点（标题与清单项一致，摘要写「待处理」），后续的成果写在这个子节点里。
3. **向用户确认清单**：清单建好后停下来，用一两句话请用户确认或调整，等用户回复后再开始。
4. **逐项解决**：一次只做一项，严格按顺序。
   - 开始前用 canvas_edit_node 把该子节点的摘要改为「进行中」。
   - 完成后把结论写进该子节点的正文，摘要改为一句话结论，并把清单节点里对应的 `- [ ]` 改成 `- [x]`（用 edits 局部替换）。
   - 做不下去或不需要了，标成 `- [~]` 并在子节点里写明原因。
5. **推进**：每完成一项，用一句话汇报，然后直接做下一项，不必每步都等用户。遇到必须由用户决定的事再用 ask_user。
6. **收尾**：全部完成后，在清单节点下新建「结论」子节点，汇总各步结论与整体答案。

## 注意

- 用户中途插话或改需求时，先更新清单（增删改步骤），再继续。
- 不要提前做后面的步骤，也不要把多项合并成一次完成。
